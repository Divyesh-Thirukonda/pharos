# Workshop deployment

Uses the existing Team 12 Kubernetes cluster and VSS/NVIDIA/CoreWeave services. No registry build, GPU deployment or changes to the shared VSS pipeline.

1. Build locally with `npm run build`, then run `python3 deploy/build_bundle.py`.
2. Upload `deploy/lab.sh` and `deploy/pharos.tar.gz` through the workshop VM's **Upload Files** control.
3. In the **Team 12 workshop VM** terminal, run `bash /path/to/lab.sh /path/to/pharos.tar.gz`.
4. Open [the workshop](https://workshop.thecosmoslabs.com) and click **App**.

The script uses exported `INGRESS_URL`, `USERNAME`, `PASSWORD`, `WANDB_API_KEY`, `WANDB_TEAM`, `WANDB_PROJECT`, `GPU_BEARER_TOKEN`, or selected keys from `/config/team-12.config`. It maps credentials to `VSS_USERNAME` and `VSS_PASSWORD` inside a new `pharos-vss-creds` Kubernetes Secret. For `VSS_URL`, an explicit override takes precedence, then the existing `video-backend-service:8000` when found, then `INGRESS_URL`. The internal service avoids the legacy ingress hostname's DNS failure inside pods. Credential values are never printed. The script prefers exported `KUBECONFIG`, then `/config/team-12-k8s.yaml`, then `/config/kubeconfig`. Required settings are checked before mutation.

`COSMOS3_REASON_URL` and `YOLO_URL` override the shared GPU service addresses. If absent, the script uses the addresses published in the [official workshop GPU guide](https://github.com/vast-data/vast-builders-challenge/blob/main/.cursor/skills/gpu/README.md): `http://166.19.38.112:8001` and `http://166.19.38.112:8002`. Cosmos discovers the current model with `/v1/models`; `COSMOS3_REASON_MODEL` is used only if present in that response. GPU and W&B credentials remain in the server-side Secret.

Only `team-12` is targeted. Resources: `pharos-bundle-0` and `pharos-bundle-1` ConfigMaps, `pharos-vss-creds` Secret, `pharos` Deployment/Service and `pharos-ingress`. An existing `/app` route is inspected first; a route under another ingress name requires `PHAROS_APP_INGRESS_NAME` set to that exact inspected name. Only its backend service is patched, with a resource-version check. Root `/` and VSS `/api` routes are preserved.

The gzip bundle is split into two ConfigMap binary payloads of at most 650,000 bytes, mounted at `/bundle`, rejoined and extracted into an `emptyDir` at `/code`. The compressed bundle limit is 1,300,000 bytes. It includes compiled frontend, backend, reviewable frontend source, design writeup and project manifests; credentials, caches and installed dependencies are excluded. The public `python:3.12-slim` image installs Debian `ffmpeg` and `ca-certificates`, installs Python requirements, and runs Uvicorn on port 8080. `IMAGEIO_FFMPEG_EXE=/usr/bin/ffmpeg` selects the Debian binary for capture and metadata: the wheel's Linux static FFmpeg 7.0.2 crashed on this HLS input. Local development keeps the bundled fallback when the override is absent. Package installation repeats on a new container; startup requires access to Debian and Python package repositories. `/health` controls readiness. The bundled HTML sets `/app/` as its base so assets and API paths work from the workshop App button. The public-data cache survives process restarts in a pod but is refetched after pod replacement.

Fresh video analysis uses bounded background jobs: up to two active and four queued. Each captures at most eight seconds, transcodes to 4 fps and at most 640 pixels wide, then sends the same MP4 bytes to Cosmos and YOLO. The response includes a SHA-256 hash and acquisition times; these are not a verified camera capture clock. Captures and results expire after 30 minutes, with additional limits of 24 jobs and 150 MiB. Cleanup runs when job APIs are accessed and workers complete; orphan captures are removed after a process restart. There is no persistent video archive. Public 511NY reachability does not establish formal feed reuse approval.

Repeat the build/upload/deploy loop after changes. Serverless W&B inference uses the existing workshop key. Optional Weave instrumentation requires `WEAVE_PROJECT` or `WEAVE_ENABLED=true` plus a team; the container then installs the optional tracing dependencies. Do not run the deploy script locally or with shell tracing (`bash -x`).

The final script check probes the running pod on localhost. Verify external access at [PharOS](https://team-12-app.thecosmoslabs.com/app/?v=pharos); a configured provider in `/app/api/health` does not prove a successful provider request. Run a live video job and inspect its raw-video hash, model IDs, detections, fresh Cosmos observation, structured verdict and component errors. Search and historical assessments are separate checks and do not prove direct video inference.
